# Ingestion API

## `POST /api/v1/events?site_key={site_key}`

Accepts a batch of tracking events for one site. The endpoint is public; the site key identifies the site and is safe to embed in pages.

### Request

The body is JSON. It may be sent as `application/json` or as `text/plain`. The SDK uses `text/plain` so browsers treat it as a simple CORS request: no preflight, and it is accepted by `navigator.sendBeacon`.

```json
{
    "events": [
        {
            "event_id": "4f9c1f4e-8a7d-4b8e-9a59-2f1f5d1f0c3a",
            "type": "campaign_impression",
            "campaign_id": "01jca7k3m0x9y2z4b6c8d0e2f4",
            "occurred_at": "2026-10-19T14:03:22.415Z",
            "visitor_id": "6b3f…",
            "session_id": "a81d…",
            "url": "https://shop.example.com/pricing",
            "referrer": "https://www.google.com/",
            "properties": { "variant": "b" }
        }
    ]
}
```

| Field                      | Rules                                                                                                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `events`                   | Required list of 1–50 events.                                                                                                                 |
| `event_id`                 | Required UUID, generated by the client. It is the idempotency key, unique per site.                                                           |
| `type`                     | Required: `page_view`, `campaign_impression`, `campaign_click` or `conversion`.                                                               |
| `campaign_id`              | The campaign's public ID. Required for impressions and clicks, optional for conversions (attributed conversion), and must belong to the site. |
| `occurred_at`              | Required date, ISO 8601 recommended. It must be within the last 7 days; future times are clamped to the time the event is received.           |
| `visitor_id`, `session_id` | Optional strings, up to 64 characters.                                                                                                        |
| `url`, `referrer`          | Optional strings, up to 2048 characters.                                                                                                      |
| `properties`               | Optional object with up to 20 keys. Values must be strings, numbers, booleans or null.                                                        |

Limits are configurable in `config/tracking.php`.

### Responses

| Status                      | Meaning                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `202 Accepted`              | The batch was processed. Each valid event is either stored or recognised as a duplicate.                                 |
| `401 Unauthorized`          | Unknown site key.                                                                                                        |
| `403 Forbidden`             | The request's `Origin` header is not the site's domain or one of its subdomains.                                         |
| `413 Payload Too Large`     | The body exceeds 64 KB.                                                                                                  |
| `422 Unprocessable Content` | The envelope is invalid, for example when `events` is missing, not a list, or has more than 50 items. Nothing is stored. |
| `429 Too Many Requests`     | Rate limit exceeded. The default is 600 requests per minute per site key and client IP.                                  |

A `202` body reports what happened to every event:

```json
{
    "accepted": 2,
    "duplicates": 1,
    "rejected": [
        {
            "index": 3,
            "errors": {
                "campaign_id": ["The campaign does not exist on this site."]
            }
        }
    ]
}
```

- `accepted`: newly stored events, queued for processing.
- `duplicates`: valid events whose `event_id` was already stored for this site, from an earlier request, a concurrent one, or earlier in the same batch. They are not counted again.
- `rejected`: invalid events by position, with validation messages. They are not stored, and resending them unchanged will fail again.

### Delivery semantics

- **Exactly-once storage per event ID.** A unique `(site_id, event_id)` constraint and an insert that ignores conflicts settle retries and races in the database.
- **Exactly-once counting.** Processing claims each stored event once, as described in [architecture.md](architecture.md).
- **SDK retries** network errors, `429` and `5xx` with exponential backoff (1 s doubling to 60 s) and the same event IDs. Other `4xx` responses are not retried. Unsent events persist in `localStorage` across page loads. On page unload the SDK sends via `sendBeacon` but keeps the events queued until a later request confirms them, so delivery is at least once and duplicates are discarded by the server.

### Example

```bash
curl -X POST "https://your-app.example/api/v1/events?site_key=pk_..." \
  -H 'Content-Type: application/json' \
  -d '{"events":[{"event_id":"'"$(uuidgen)"'","type":"page_view","occurred_at":"'"$(date -u +%FT%TZ)"'"}]}'
```
